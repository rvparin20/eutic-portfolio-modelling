# Portfolio Modelling & Regime Detection

A quantitative finance project applying stochastic asset-path simulation,
maximum-likelihood parameter calibration, and unsupervised regime
detection to portfolio allocation.

Built while studying derivatives and portfolio theory with EUTIC
(Edinburgh University Trading & Investment Club) — no-arbitrage pricing,
Black-Scholes, Monte Carlo methods, and Sharpe ratio optimisation.

## What this does

1. **Calibrates Geometric Brownian Motion (GBM) parameters** — annualised
   drift (μ) and volatility (σ) — for each asset from historical daily
   log returns, using maximum likelihood estimation.
2. **Runs Monte Carlo forward simulations** using the calibrated
   parameters to project a distribution of future price paths, not just
   a single point forecast.
3. **Detects market regimes** ("calm" vs "stressed") using k-means
   clustering on rolling realised volatility and momentum features —
   an unsupervised approach to identifying structural shifts in market
   behaviour, rather than relying on a fixed threshold.
4. **Allocates portfolio weights** using a Sharpe-ratio-weighted
   heuristic, adjusted for the currently detected regime (reducing risk
   exposure automatically when the model detects a stressed regime).

## Note on data

This project uses **synthetic price data** (Geometric Brownian Motion
with a deliberate regime shift partway through), generated by
`data/generate_sample_data.py`. This keeps the project fully
reproducible without depending on an external market data API. The
methodology — calibration, simulation, regime detection, allocation —
is identical to what would be used on real historical price data;
swapping `data/sample_prices.csv` for a real dataset (same column
format: `date` index, one column per asset) requires no other code
changes.

## Key modelling choices, and their limitations

- **GBM assumes constant drift/volatility within a calibration window.**
  This is a standard simplifying assumption in introductory
  quantitative finance, but real markets exhibit volatility clustering
  and fat tails that GBM doesn't capture — hence layering regime
  detection on top, rather than relying on GBM alone.
- **The portfolio allocation assumes zero correlation between assets**
  unless a correlation matrix is explicitly supplied — noted directly
  in the code, since this materially understates portfolio risk in a
  correlated basket.
- **Regime detection uses unsupervised clustering (k-means), not a
  labelled dataset** — regimes are inferred purely from the structure
  of rolling volatility/momentum, which is why they're validated
  against synthetic data with a known, deliberately-injected regime
  shift.
